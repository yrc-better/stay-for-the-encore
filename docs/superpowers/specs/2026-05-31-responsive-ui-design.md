# 乐队模拟器响应式 UI 设计

## 目标

让《乐队模拟器》在电脑网页和手机浏览器上都有清晰、稳定、可操作的布局。改动只覆盖 UI 结构和样式，不改变游戏规则、行动数值、事件内容、存档格式或结局逻辑。

## 设计读法

这是一个游戏模拟器的产品界面，不是营销页。视觉方向继续保持暗色、排练室、乐队档案感；布局要服务重复游玩、快速扫描和触控操作。

## 桌面布局

桌面宽度大于等于 1100px 时使用三栏：

- 左栏：乐队名、月份、体力、关键能力、装备。
- 中栏：当前事件、个人行动、乐队行动、阶段推进按钮。
- 右栏：成员关系、履历。

页面主体限制最大宽度，避免宽屏时中栏过长。三栏使用稳定的 CSS Grid 轨道，左右栏宽度固定，中栏自适应。

## 平板布局

宽度 760px 到 1099px 使用两列：

- 左列：状态、装备、成员关系、履历。
- 右列：当前事件、行动、阶段推进。

这样避免三栏在小桌面或横屏平板上被挤压。

## 手机布局

宽度小于 760px 使用单列：

1. 状态摘要。
2. 当前事件。
3. 行动选择，其中个人行动和乐队行动保持左右并列。
4. 阶段推进按钮。
5. 装备、成员关系、履历。

行动按钮填满各自行动列，触控高度稳定。页面横向不得溢出，文本不得挤出按钮或面板。

## 组件边界

- `GameLayout.tsx` 负责把现有内容拆成可响应式排序的区域。
- `ActionPanel.tsx` 保持行动分组职责，不承载页面级布局。
- `styles.css` 负责桌面、平板、手机断点和视觉密度。
- `App.test.tsx` 增加结构测试，防止响应式分区被回退成难以控制的单块布局。

## 乐队命名

开局页提供 `乐队名` 输入框。玩家输入后选择职业，乐队名写入 `GameState.bandName` 并显示在状态摘要顶部。空输入和旧存档缺失字段时统一使用 `未命名乐队`。第一版不提供中途改名功能。

## 验收

- 桌面 1280px 宽度下显示三栏布局，没有水平滚动。
- 手机 390px 宽度下显示单列页面布局，个人行动和乐队行动在行动区内左右并列且无重叠。
- 平板 820px 宽度下显示两列页面布局，行动区内个人行动和乐队行动左右并列，且状态区不相互挤压。
- 自动测试、类型检查和生产构建通过。
