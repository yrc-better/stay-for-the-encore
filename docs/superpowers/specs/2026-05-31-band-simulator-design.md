# 《乐队模拟器》设计文档

## 目标

《乐队模拟器》是一款可发布到网页上的剧情经营模拟游戏。玩家扮演一名吉他手，从大四毕业演出前一个月开始，进入一支固定校园乐队，并在毕业后经历乐队创作、成员关系、商业压力、演出、合约、荣誉和人生终章。

第一版选择“剧情体验优先”。目标不是立即铺满几十年完整沙盒，而是先做出可游玩的核心体验：固定四人乐队、月推进、体力透支、个人行动、乐队行动、装备栏、行动反馈、成员关系、履历记录，以及可调出的结局评价页。

整体气质比例为：70% 摇滚传记，10% 校园青春，20% 现代独立经营。现实知名乐队和日本乐队动漫仅作为结构与气质参考，例如创作权冲突、商业压力、队内裂痕、舞台人格、成员依赖与疏离。角色、乐队名、事件和剧情必须原创化。

实现数据以 [《乐队模拟器》数据规格附录](./2026-05-31-band-simulator-data-spec.md) 为准。设计文档描述产品方向和系统边界，数据规格附录定义第一版默认数值、事件结构、作品状态机、称号判定和内容量。

## 第一版范围

第一版包含：

- 开局选择吉他手出身路线。
- 校园序章，从大四毕业演出前一个月开始。
- 毕业后主线的早期月推进循环。
- 固定四人乐队：玩家吉他手、主唱、贝斯、鼓手。
- 个人行动和乐队行动。
- 体力系统和透支风险。
- 装备栏：吉他、效果器、音箱或插件。
- 行动和剧情选项后的事件反馈。
- 成果履历：Demo、演出、合约、奖项、销量、媒体评价等。
- 可调出的结局评价页。
- 浏览器本地存档。

第一版自然可玩范围到 `2027-08`，即校园序章 1 个月加毕业后早期主线 3 个月。结局页在第一版中通过退役、告别演出、寿命测试状态或开发预览入口调出，不要求自然推进完整几十年人生。

第一版不要求完成：

- 完整几十年生涯内容。
- 大量专辑、巡演和完整寿命事件库。
- 节奏按键演奏玩法。
- 在线账号、云存档、排行榜。
- 复杂 3D 场景。

## 玩家身份

玩家固定扮演吉他手。开局选择出身路线，影响初始数值、早期事件、可见选项和剧情倾向。

出身路线：

- 技术宅：技术较高，舞台表现较弱，更容易触发练习、设备、演奏瓶颈相关剧情。
- 创作型：创作较高，更容易触发编曲、作品方向、创作权冲突相关剧情。
- 舞台型：舞台表现较高，名声增长更快，但更容易积累压力和透支风险。
- 叛逆型：选择更极端，更容易触发商业冲突、成员冲突和高风险传奇事件。

音乐风格采用“开局倾向 + 后续转型”模式。开局可有摇滚、朋克、金属、流行摇滚、独立/另类等倾向，后续由行动、专辑、演出和事件逐步形成风格标签。

## 时间推进

校园序章和毕业后主线都按月推进。游戏从大四毕业演出前一个月开始，这个月是校园序章的起点。

每个月流程：

1. 月初恢复部分体力，并结算上月持续状态。
2. 生成或推进当前事件。
3. 玩家执行个人行动或乐队行动。
4. 每次行动或剧情选项后进入事件反馈。
5. 玩家可继续行动，或手动进入下个月。
6. 月末检查毕业演出、合约、健康、关系破裂、成员离队等关键触发条件。

体力可以透支。透支不会立即禁止行动，但会增加压力、健康损失、演出失误、成员冲突、负面事件和极端剧情的概率。关键剧情和特殊行动也可以透支，以形成“燃烧自己换取机会”的传记感。

## 核心数值

常驻核心数值：

- 体力：每月行动资源，可透支。
- 技术：影响演奏、排练、录音和专业评价。
- 创作：影响写歌、团体创作、专辑质量和风格突破。
- 舞台：影响演出表现、粉丝增长和现场事件。
- 健康：影响长期生涯、透支风险和寿命。
- 压力：影响冲突、崩溃事件和创作爆发。
- 关系：玩家与乐队成员的总体关系入口，具体成员仍有独立关系。
- 名声：影响演出机会、媒体关注和合作邀请。
- 财富：影响装备、生活压力、录音资源和谈合作。

乐队层面影响项：

- 默契：影响排练、团体创作和演出稳定性。
- 作品质量：影响 Demo、专辑、现场口碑和合约机会。
- 粉丝/口碑：影响演出收益、地下影响力和媒体事件。
- 成员关系：每名成员与玩家、乐队整体之间都有关系状态。
- 乐队资金：用于录音、宣传、巡演和特殊机会。

销量、荣誉、合约、专辑成绩、奖项、媒体评价不堆在常驻状态栏里，而是作为成果和事件写入履历，并影响结局评价。

## 乐队与角色

开局乐队为四人固定成员：

- 玩家：吉他手。
- 主唱：承担舞台焦点和歌词/表达压力。
- 贝斯：可作为稳定器、沉默观察者或隐藏矛盾来源。
- 鼓手：负责节奏与现场爆发，容易成为排练冲突和演出状态的关键。

毕业后可以通过特定事件触发成员离队、新人加入、回归或阵容重组。后续可扩展键盘、第二吉他、制作人型成员。第一版先保证固定四人关系线可玩。

角色性格和能力可以参考知名乐队成员的功能结构，但不能直接复制真人姓名、外观、完整经历或可识别组合。

## 行动系统

行动分为个人行动和乐队行动。UI 中两类行动要使用明显不同的色块，以便快速区分。

个人行动：

- 练琴：提升技术，消耗体力，可能增加压力。
- 写 Riff：生成个人创作素材，提升创作，可能触发灵感事件。
- 研究风格：听唱片、扒谱、看现场、研究曲风，增加风格标签和创作上限。
- 打工：增加财富，消耗体力，可能影响练习和关系。
- 休息：恢复压力或健康，牺牲发展机会。
- 社交：改善人脉，可能触发演出、合约或关系事件。
- 逛乐器店：查看、购买、试用或触发装备事件。
- 自我突破：高消耗、高风险行动，可能大幅提升技术、创作或舞台，也可能造成健康和压力代价。

乐队行动：

- 排练：提升默契、演出稳定性和作品质量。
- 团体创作：把个人 Riff 或灵感发展成歌曲，影响作品质量、创作权、成员关系和乐队风格。
- 录音：把已有歌曲录成 Demo、单曲或专辑成果。具体结果由阶段、资源、合约和作品状态决定。
- 演出：获得名声、财富、粉丝和现场履历，也可能触发失误或名场面。
- 成员谈话：处理冲突、缓和关系、发现隐藏压力或推进成员线。
- 宣传：提升曝光、粉丝和媒体关注，可能增加商业压力。
- 谈合作：触发 Livehouse、经纪、唱片、品牌或制作人合作。
- 休整：恢复乐队状态、降低冲突和疲劳。

维护装备、选歌单、录音棚预约不作为常规月行动。维护装备放入装备事件或乐器店交互；选歌单放入演出前事件；录音棚预约合并进“录音”。

## 装备系统

主界面包含装备栏，展示当前使用的吉他、效果器、音箱或插件。

装备影响：

- 演出稳定性。
- 音色和风格标签。
- 录音质量。
- 技术发挥。
- 舞台表现。
- 特定剧情触发。

装备来源：

- 打工和演出收入购买。
- 二手市场或乐器店。
- 剧情赠送。
- 赞助或代言。
- 合约合作。

重要装备会进入履历，例如第一把琴、巡演用琴、坏掉的效果器、成名后代言款。装备不应变成纯数值堆装，应服务音乐风格和角色记忆。

## 事件反馈

玩家点击行动或剧情选项后，必须进入事件反馈弹窗或反馈页，而不是只修改数值。

反馈内容包括：

- 发生了什么。
- 成员反应。
- 数值变化。
- 获得或失去的履历。
- 是否触发后续事件。

普通行动反馈较短。例：“你练琴到凌晨，手指发麻，但终于弹顺了那段过门。”

关键剧情反馈较长，可以包含对话、成员关系变化、隐藏标记和后续事件。若行动导致重大结果，例如成员爆发、健康崩溃、签约邀请或演出事故，反馈确认后可直接进入新的剧情事件。

## 结局与职业称号

游戏有寿命系统。寿命结束会触发生涯结局。玩家也可以选择告别演出或退役，提前进入结局评价。

第一版结局页只需要能被调出：寿命结束、告别演出、退役或开发预览入口都可以进入结局评价页。不要求第一版完成完整几十年人生内容。

游戏过程中不显示“称号倾向”。不在主界面提前提示玩家正在变成哪种最终称号。系统只展示可观察信息：数值、关系、状态、装备、履历、作品、演出、合约、成员状态。最终职业称号只在结局评价或少数重大媒体/荣誉事件中出现。

职业称号池：

- 技术宗师：技术、稳定性、专业口碑极高。
- 吉他英雄：舞台、粉丝、巡演名场面极高。
- 声音塑造者：创作、专辑评价、风格影响力极高。
- 乐队灵魂：关系、默契、长期留队、关键和解事件突出。
- 地下传奇：商业成绩一般，但独立口碑和现场圈层影响力极强。
- 白金巨星：销量、财富、媒体曝光和主流奖项突出。
- 实验先锋：风格融合、转型、争议专辑和创新评价突出。
- 燃烧的传说：透支、冲突、极端事件、短期巅峰和毁灭性代价突出。
- 无名匠人：技术或创作不错，但名声有限，适合低商业但稳定路线。
- 失落天才：早期潜力极高，但因关系、健康、合约或选择错失巅峰。

结局由“人生终点 + 职业称号 + 履历摘要 + 关键遗憾/荣耀”组合生成。

## UI 结构

主界面采用单页游戏应用布局。

核心区域：

- 顶部或主标题区：当前年月、阶段、主要事件。
- 左侧角色区：玩家姓名、出身路线、风格倾向、体力和核心数值。
- 左侧装备栏：吉他、效果器、音箱或插件。
- 左侧状态栏：本月状态，如睡眠不足、新歌未定稿、毕业演出压力上升。
- 中央剧情区：当前事件、行动结果、成员对话、剧情选择。
- 行动面板：个人行动与乐队行动分组，用不同色块呈现。
- 右侧乐队区：成员关系、成员状态、乐队名称。
- 右侧履历区：Demo、演出、合约、专辑、荣誉等成果。
- 结局页：可调出的职业称号和人生评价。

视觉主调为深色后台、Livehouse、城市夜晚、唱片履历感。校园序章保留少量练习室和毕业前青春感。经营界面要清晰，避免装饰遮挡信息。

## 技术结构

推荐技术栈：

- React。
- Vite。
- TypeScript。
- CSS Modules 或普通 CSS，先不引入复杂 UI 库。
- localStorage 存档。

模块边界：

- `gameState`：当前年月、玩家、乐队、数值、履历、事件队列。
- `actions`：个人行动和乐队行动定义。
- `events`：剧情事件、触发条件、选项和反馈。
- `characters`：玩家路线、成员设定、成员状态。
- `equipment`：吉他、效果器、音箱或插件。
- `outcomes`：数值变化、履历写入、事件触发。
- `ending`：隐藏称号判定和结局生成。
- `storage`：存档、读档、重置。
- `ui`：页面、面板、弹窗、反馈页。

游戏逻辑尽量写成纯函数，UI 只负责展示和触发操作。这样后续可以为行动结算、事件触发、称号判定和存档迁移写自动化测试。

## 数据流

一次行动的数据流：

1. UI 显示当前可用行动。
2. 玩家点击行动。
3. 规则层检查体力、阶段、角色状态、乐队状态和事件锁定。
4. 规则层生成结果：数值变化、关系变化、履历、反馈文本、后续事件。
5. UI 展示事件反馈。
6. 玩家确认反馈。
7. 状态写入存档。
8. UI 返回主界面或进入新事件。

一次剧情选项的数据流相同，但入口是当前事件选项而不是行动按钮。

## 错误处理

- 存档读取失败时，显示“存档损坏或版本不兼容”，提供新游戏和清除存档入口。
- 行动条件不满足时，不静默失败，显示原因，例如体力不足但可透支、当前没有可录音歌曲、成员关系过低无法谈合作。
- 透支导致健康或压力风险时，反馈必须明确说明后果。
- 事件数据缺字段时，开发环境报错，生产环境回退到安全文本并保留状态。
- 结局页数据不足时，使用已记录履历生成简短评价，不阻断页面。

## 测试策略

第一版需要覆盖的测试：

- 开局路线正确设置初始数值。
- 月推进恢复体力并结算持续状态。
- 体力可透支，并产生压力或健康风险。
- 个人行动和乐队行动能正确改变状态。
- 团体创作能把创作素材推进为作品。
- 录音根据当前作品和资源生成 Demo 或正式成果。
- 行动后一定生成事件反馈。
- 事件反馈确认后能返回主界面或进入后续事件。
- 装备能影响相关行动结果。
- 游戏过程不显示隐藏称号倾向。
- 结局页能从退役、告别演出和寿命结束入口调出。
- 结局称号根据履历和数值生成。
- localStorage 存读档可用。

## 发布目标

第一版发布目标是一个可在浏览器中游玩的单页游戏。开发完成后可以通过静态站点部署，例如 GitHub Pages、Vercel 或 Netlify。构建产物应为静态资源，便于后续发布。
